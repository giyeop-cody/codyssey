# Windows 재개 검증 — 2026-10-12

이전 작업은 Advanced 10개 미션의 원문 요구와 평가 187문항을 실제 산출물과 대조하는 검증이었다. `3b18d05` 체크포인트와 해당 gitlink 21개를 복원했다. 필요한 직계 서브모듈만 초기화했고 허브 내부 중복 clone과 taskmap 역참조를 재귀 초기화하지 않았다. 원문 taskmap/evalmap은 별도 sibling clone을 사용한다.

## 반영한 정정

- A2-1의 “lr=0.5 이상에서 발산 예시”는 lr=1.5 그래프로 충족하며, 모든 lr≥0.5가 발산하는 보편 명제로 해석하지 않는다. .5 즉시 수렴, 1 왕복, >1 발산과 y_true 공란에 대한 y=0/1 가정을 함께 유지했다.
- A3-2의 cross-06은 T29가 5프레임 연속 유지되지 않아 switch0이다. 기존 trace를 바꾸지 않고 잘못된 설명만 정정했다. 30개 선택 사건의 CSV를 실제 기록으로 채웠고 사건별/조건별 계수와 이미지 SHA를 검증했다. 군중 속 단일 대상·디지털 gain·정지 후 재이동 미확인·Codex 검토라는 제한을 명시했다.
- 누락된 `tools/verify_submission.py`, `tools/run_verification_tests.py`, A4-1 `scripts/verify_external_corpus.py`를 작성했다. 존재하지 않았던 run_cnn 명령을 실제 run_transfer 진입점으로 고쳤다.
- Windows 체크아웃에서는 LF 소스·고정 fixture를 보존한다. 역사 CSV는 `-text`로 바이트를 보존하고, 고정 fixture CSV만 LF를 지정했다. 원문 저장소는 `git clone -c core.autocrlf=false ...`으로 받아야 SHA가 일치한다. 현재 원문 텍스트는 Git blob과 같은 LF로 복원했다.
- A3-2 테스트 입력 영상을 임시 폴더에서 생성한다. A5-2 원문 생성기를 임시 폴더에서 실행하고 LF 인코딩으로 원본 CSV SHA를 확인하여 복원한다. 원문 생성기 자체는 변경하지 않았다.
- A6-2 PyTorch class index를 long으로 지정해 Windows NumPy int32 문제를 해결했다. 캐시 없는 AAPL 고정 입력 복원·손상 fixture 거부 검사를 추가했다.
- A3-1 합성 생성기의 한글 파일명 저장을 imencode/tofile로 고쳤다. 이 변경은 영상 픽셀·생성 시드를 바꾸지 않는다. OCR 테스트에는 설치된 Windows CJK 글꼴을 명시적으로 전달한다. 역사 실험 해시가 포함한 PDF/스캐너 소스는 유지했다.

## 현재 증거와 실행

`reports/current-verification/tests.json`은 이번 Windows pytest 결과이며 이전 Mac 334/0skip/1xfail과 구분한다. `tools/verify_submission.py`는 187개 원문 문항/답변, 10쌍 원문 SHA, 선택 시각 검토 계수·이미지 SHA·worksheet, 주가 fixture SHA를 검사한다. 이것이 모든 요구사항 충족을 인증하지는 않는다.

작업 폴더 바깥으로 설치하지 않았다. Python 3.12.14 환경은 sibling `.venv-verification`, Tesseract 5.5.3/언어팩125는 `.ocr-env`에 있다. 이 환경·공개 원본 캐시는 Git에 포함하지 않는다. OCR runner는 `TESSERACT_DIR`와 `TESSDATA_PREFIX`를 설정한다. 수동 실행은 해당 환경변수를 설정하고 `python -X utf8`를 사용한다.

```powershell
& ../.venv-verification/Scripts/python.exe -X utf8 tools/verify_submission.py
& ../.venv-verification/Scripts/python.exe -X utf8 tools/run_verification_tests.py
& ../.venv-verification/Scripts/python.exe -X utf8 -m pytest -q tools/test_input_downloaders.py
```

다운로더의 손상 캐시 복구·upstream SHA 거부·실패 시 기존 파일 보존/임시 파일 정리·offline 검사 실패를 별도 임시 입력으로 검증했다. 실제 원본 입력 검사와 혼동하지 않는다.

## 남은 제한

20 Newsgroups는 sklearn 소스가 명시한 공식 MIT 배포 경로에서 14,464,277바이트 원본을 받아 sklearn의 SHA256과 일치함을 확인했다. 3,618문서 × 10개 독립 TF-IDF/cosine 대조와 NSMC 4,000문서 × 10개 대조가 이번 Windows 실행에서 통과했다. Figshare 403은 해결 경로를 기록한 과거 장애이며 현재 미완료 항목이 아니다. sklearn fetcher의 BSD를 코퍼스 사용 허가로 간주하지 않는다.

A3-2는 조건별 선택 사건 기록을 채웠지만 통제된 단일 객체·물리적 조명 변화·정지 후 재이동·학습자 본인의 수동 측정을 모두 충족했다고 주장하지 않는다. A3-1 선택 v3 키스톤 expected failure는 유지한다. 기존 Mac GUI와 CNN 학습은 이번 Windows에서 새 실행한 증거가 아니다.

최종 제출 완료·전체 요구 인증을 주장하지 않는다. 핸드오프의 “문제 없으면 최종 커밋·푸시” 조건은 남은 차이가 해결되기 전 실행하지 않는다.

정지한 자세는 보이나 이동→정지→재이동을 이 기록만으로 모두 입증하지는 않는다.
원문은 물리 조명·고립된 장면·별도 재이동 입증을 명시하지 않으므로 이를 추가 필수 조건으로 단정하지 않는다.
군중 속 대상·디지털 gain·Codex 검토의 실제 범위는 계속 명시한다.

1. 20NG 장애: 공식 동일 바이트 원본 복원 완료. `A4-1/scripts/restore_20ng_archive.py`와
   `reports/20ng-original-input.json`에 재현 경로·해시를 기록했고 두 코퍼스 oracle을 실행했다.
2. A3-2 관찰: `scripts/audit_review_protocol.py`, `render_pause_context.py`와
   `reports/manual-review/pause-context/`에 적격성 검토 자료를 추가했다.
   계수 검증과 조건 적격성을 구분하며 학습자 자신의 경험을 Codex 관찰로 대체했다고 인증하지 않는다.
   학습자 관찰 기록을 보충할 때는 실제 대상·프레임 구간·관찰자와 조건을 기록한 뒤 계수 검사를 재실행한다.
3. A3-1 v3: 알려진 실패는 기본4점 scanner 밖의 추가 실험이다. 기본 경로의 테스트는 통과했다.
   수정한다면 라인 기반 정면화 후보를 별도 경로로 구현하고, 실패 회귀의 기존 오차 기준을 유지하며,
   역사 source hash가 걸린 실사진 실험을 동일 입력으로 다시 실행한다. xfail을 삭제해 성공으로 처리하지 않는다.
4. 공개 순서: 미션 → 스터디로그 → 허브의 명시적 gitlink → 통합 저장소.
   허브의 하위 모듈은 재귀 초기화하지 않는다. 원격 최신 상태를 비교하고 force push 없이 진행한다.

현재 알려진 실패와 관찰 범위 차이가 남았으므로 “문제 없으면 모두 커밋·푸시” 조건의 최종 공개는 보류한다.
수정·증거·계획은 작업 폴더에 보존했다. 이것은 전체 요구 완료 인증이 아니다.
